Datum

Sovereign forms.

Datum is open-source forms infrastructure you run yourself. Define a form once, deliver it as a web form, a PDF or a printed page, and keep the forms and the records in your own hands.

Open the live demo Documentation Source on GitHub

One definition

A form is a single JSON file holding its fields, rules, pages and PDF layouts. It lives in your repository.

A visual builder

People build and edit forms without writing code. What the builder saves is that same file.

Drop-in components

The form loads with a script tag on any page and is drawn in your own design system's look.

Checked twice

The same validation program runs in the browser and again on your server, inside a WebAssembly sandbox.

PDFs and signatures

The form renders to PDF or fills a template you already have. PDFs can be tagged, produced as PDF/A and digitally signed.

Multi-page journeys

One form can be asked a page at a time, with pages that appear or are skipped depending on the answers.

Tests for forms

Short scenarios kept with the form check its rules and paths, in the browser and on the server.

Nothing phones home

Every asset is a file you host. A form runs air-gapped, in the browser alone or behind your own server.

How it works

One form definition passes through four steps, in this order.

  1. 01

    Build

    Someone designs the form in the builder, or writes the JSON directly. Either way the result is one definition file.

  2. 02

    Deliver

    The engine reads the definition and draws it on your page. Rules and validation run as the person fills it in.

  3. 03

    Check

    On submit, your server runs the same validation program in a sandbox. The browser's word is never taken for it.

  4. 04

    Record

    The accepted submission is stored where you decide, and the same definition produces the PDF record.
